# Задание 1. Уровень 1 и 2

## Уровень 1. Проектирование. Разбиение на микрофронтенды

### 1. Предварительный анализ

#### Оценка сложности проекта
Проект представляет собой единое приложение со следующими функциями:
- Регистрация и авторизация пользователей
- Работа с профилем пользователя
- Добавление/удаление фотографий
- Вывод каталога фотографий
- Работа с лайками у фотографий

На данном этапе проект не является сложным и может поддерживаться одной небольшой командой.  
Однако в будущем проект может разрастись и получить новые функции.

> Так как пример тестовый, мы не можем сказать, какие могут быть планы у бизнеса.  
> Для продолжения работы будем считать, что в будущем предполагается расширение функционала проекта, увеличение конверсии и разработка модулей разными командами.

#### Цель перехода
Разделение монолитного приложения на несколько микрофронтендов позволит:
- Обеспечить возможность расширения приложения.
- Позволить нескольким командам вести разработку разного функционала.
- Обеспечить возможность независимой разработки и развертывания разных частей приложения.
- Улучшить масштабируемость и производительность отдельных сервисов.

### 2. Определение бизнес-функций

На данном этапе функциональность можно разделить на следующие части:

#### 1. login
Сервис для авторизации, регистрации и деактивации пользователей.  
Вынесение в отдельный модуль позволит использовать данный сервис не только в этом продукте, но и в смежных.  
Также в будущем будет проще добавлять новые методы авторизации, независимо от другой функциональности.

#### 2. user account
Модуль, отвечающий за работу с профилем пользователя.

#### 3. photo
Сервис для работы с фотографиями (добавление, удаление, отображение), а также учета лайков.

> В описании нет информации о том, будет ли учет лайков относиться только к фотографиям или появится необходимость учитывать лайки для других сущностей (например, профиля).  
> Поэтому на данном этапе разделения функция "учет лайков" привязана к фотографиям.

#### 4. host
Основной модуль. Отвечает за объединение всех микрофронтендов и их компоновку в единую страницу.

### 3. Методы реализации

#### Метод интеграции
В качестве метода интеграции выбран **Run time**.  
Этот подход позволит:
- Выполнять независимые развертывания
- Разделить работу над модулями между разными командами
- Обновлять отдельные модули без влияния на остальные

Так как раздел с каталогом фотографий будет использоваться чаще, то при росте аудитории такой подход позволит масштабировать только этот раздел.

#### Метод композиции
Система лайков и загрузка фотографий — важные элементы системы, предполагающие интерактивное взаимодействие.  
В связи с этим можно рассмотреть две стратегии: **клиентская композиция** и **гибридная**.

Так как мы не знаем об опыте команды, которая будет заниматься проектом, выбрана **клиентская композиция**.  
Она обеспечит хороший пользовательский опыт и не будет зависеть от уровня подготовки команды.  

#### Выбор инструмента
На данный момент у нас нет информации о будущей команде проекта. У нас есть два инструмента на выбор: **Single SPA** и **Module Federation**.

> Оба инструмента подходят для независимого развертывания и масштабируемости.

**Webpack Module Federation**
- **Плюсы:**
  - Проще в управлении зависимостями, чем Single SPA.
  - Не требует сложной настройки и интеграции.
  - Обеспечивает оптимальную производительность.

- **Минусы:**
  - Нельзя использовать разные фреймворки для отдельных модулей.

**Single SPA**
- **Плюсы:**
  - Гибкость в выборе фреймворков для каждого модуля.

- **Минусы:**
  - Сложнее в управлении зависимостями по сравнению с Webpack Module Federation.
  - Требует более сложной настройки и интеграции.

На данном этапе развития проекта предлагается использовать Webpack Module Federation по следующим причинам:
1. Этот инструмент обеспечивает хорошую производительность, масштабируемость и независимое развертывание.
2. Для его настройки и дальнейшего управления зависимостями не потребуется значительных ресурсов команды.
3. Реализацией смогут заниматься команды с любым уровнем опыта.
